# 需求基线 v0.1 · 方案库（可复用抽取方案）

日期：2026-11-13。状态：草案，待独立评审。范围：只定义需求与验收，不含实现。

## 1. 要解决的问题

现状：抽取方案（契约 / 工作解释）按**说明文本哈希**复用。用户在同一供应商的同类文件上重复上传说明才能命中，且系统里没有任何地方能看到"我配置过哪些供应商、哪些方案、上次用的是哪个"。

目标：把确认过的规则变成**用户可管理的资产**，让重复来表时免说明、可一键沿用、可随时改名与切换，同时不牺牲正确性与可追溯性。

## 2. 用户价值（判据）

| 价值 | 可验证的用户行为 |
|---|---|
| 省重复劳动 | 每周同供应商来表，不再上传说明，直接运行 |
| 心里有数 | 打开方案库能说出"我有哪几个供应商、几个方案、各是什么状态" |
| 会挑不会猜 | 新文件到达时能从已有方案里快速挑一个，不必重建 |
| 错了能追 | 任意一次运行能查到用了哪个方案、哪个版本、是否沿用 |

## 3. 对象模型

方案（Plan）是用户可见的复用单位，规则来自已确认的契约或已登记的工作解释。

```text
Plan
  id                 系统生成，稳定不变
  name               用户自定，可随时改
  supplier           供应商标识（用户确认）
  docType            单证类型/模板（用户命名，同一供应商可多个）
  contractRef        { requirementsDigest | contractVersion | approvedAt }
  status             候选 / 已确认 / 停用
  aliases[]          可选，用于提示匹配
  sampleFiles[]      可选，用于展示"像这样"
  lastUsedAt / runCount / lastDecision   只读，由运行推导
```

命名语义（必须写进 UI 文案）：

- `name` / `supplier` / `docType` 是**标签**，改名只改显示，不重算规则、不影响历史运行的正确性判定。
- `contractVersion` 是**规则版本**，系统生成、不可改名；规则变更产生新版本，旧版本保留。
- 历史运行记录 `planId + contractVersion` 快照；方案改名后，历史列表显示当前名，并保留当时的名字。

## 4. 三条用户路径

| # | 场景 | 用户动作 | 系统行为 |
|---|---|---|---|
| L1 | 查看已有配置 | 打开「方案库」 | 列出方案：名称、供应商、单证类型、状态、最近使用时间、最近一次运行结论；可改名、停用、删除（删除需二次确认并说明历史运行仍保留） |
| L2 | 新文件挑旧方案 | 上传/选择文件后，在「抽取方案」处选择已有方案 | 选中后显示"将按〈供应商·类型〉vN 抽取"；运行记录绑定该方案与版本 |
| L3 | 新建并命名方案 | 首次确认候选契约后归档 | 弹出归属表单：供应商、单证类型、方案名（三者可预填建议值，用户可改）；确认后进入方案库 |

## 5. 复用与降级（沿用已定设计）

```text
上传文件（说明可选）
  ├ 有说明且哈希命中已确认契约 → 强复用（现状保留），并提示可归档为方案
  └ 无说明 → 方案匹配
       高置信唯一 → 预选方案 + 显式横幅 + 一键运行
       多候选     → 必须用户选择，不自动取最近
       无候选     → 走新单证流程（观察原文 → 候选契约 → 确认）
  → 运行后校验：结构自检 + 独立检查
       PASS  → 完成，更新 lastUsedAt
       异常   → 标 REVIEW，提示"版式可能变化"，建议新建版本；不回写"自动适用"
```

## 6. 交互落点

- 现有单页（`web/app.js`、`web/index.html`）：新增「方案库」视图；现有上传对话框加「抽取方案」选择区；结果页/运行卡片显示 `planId + contractVersion`。
- 复用入口保留两条：说明哈希（强确定）与方案（便捷层）。

## 7. 验收用例

| ID | 用例 | 通过判据 |
|---|---|---|
| AC-1 | 打开方案库 | 显示所有方案及 名称/供应商/类型/状态/最近使用/最近结论；空库显示引导而非空白 |
| AC-2 | 改名 | 改名后列表与运行页显示新名；契约版本与历史结论不变 |
| AC-3 | 挑旧方案 | 新文件选旧方案后，运行记录含 planId 与 contractVersion，结果页可见 |
| AC-4 | 无说明高置信 | 预选方案并以横幅显式告知，用户可直接运行或更换；不静默 |
| AC-5 | 多候选 | 不自动选择，列出候选由用户点选 |
| AC-6 | 已有结果但未确认 | 不进入自动复用池，只作为"从历史创建方案"的线索 |
| AC-7 | 规则变更 | 生成新版本或新方案，旧方案与旧运行保留可查 |
| AC-8 | 复用后检查异常 | 结果标 REVIEW 并提示可能版式变化，方案状态不被自动升级 |
| AC-9 | 停用/删除 | 停用后不出现在匹配候选；删除需二次确认，历史运行仍可查 |

## 8. 非目标

- 不做完全静默自动抽取（首次启用某方案自动复用前仍需一次显式同意）。
- 不改变"只有人能确认契约"这一约束。
- 不含运价入库与查询分析（属另一条链路）。

## 9. 待评审确认

1. 方案与契约的绑定粒度：一个方案是否允许绑定多个说明哈希（多来源），还是严格 1:1。
2. 删除语义：物理删除还是仅停用（建议仅停用，保留可追溯）。
3. 历史运行的方案名：显示当前名 + 保留快照名，还是一次性快照（建议前者 + 悬停显示原名）。
