# 本地 Agent 工作台产品验收基线

2026-11-03。范围已冻结。本文件定义本轮 MVP 和产品验收，不代表实现已通过。

用户在一个本地页面选择运价文件，用自然语言交给真实 Agent，看到工具执行和修复过程，最后核对抽取记录与独立检查。已有 TypeScript 宿主、Pi Agent Loop、隔离执行和业务账本继续承担执行责任。

```text
选择原文件和本单证说明 -> 输入要求 -> 真实 Agent 调用工具
                                     |
                原文盘点 -> 抽取 -> 后处理 -> 独立检查
                              ^                 |
                              +-- 新轮次修复 <--+
                                     |
                  结果记录 + 原文坐标 + 检查报告
                                     |
                  继续追问，或带前文发起关联的新运行
```

## 最小完整范围

页面只有工作会话、执行过程、结果证据三个主要区域。用户能够新建会话、选择已有会话、发送消息、刷新后查看持久消息。消息展示用户原文、Agent 实际回复、可公开的工具事件。工具事件是执行记录，不包装成隐藏思维链。

初次打开提供现有可运行试点输入。用户也能上传一个原文件和对应说明，明确看到选中的名称与类型。原件范围沿用后端已支持的 XLSX、表格 PDF、DOCX、PNG、JPEG。上传仅导入副本。说明沿用已有工作解释匹配规则。未知说明、缺少说明或不支持的格式必须给出可操作的阻断原因。上传成功不能被描述为已经支持任意业务规则。

会话与运行分别展示身份。一段对话可以关联多个运行。后续消息保留前文、原文件和所选结果上下文。追问结果时，Agent 必须实际读取或接收该结果证据。需要重新执行的后续消息创建关联的新运行，并明确显示新运行。已有终态保持可审计。中断运行仅按现有恢复规则继续，保留原预算；收费回执不确定时不能自动重试。

单个会话只同时执行一条用户请求。执行中保留输入草稿，发送按钮说明等待原因。MVP 不要求暂停、取消、排队或并发调度。这些按钮不得以无效占位形式出现。

结果区以最终记录表为主。每轮可查看脚本或直接抽取响应、原始结果、后处理结果、检查报告和错误证据。问题列表展示原文坐标、预期值、实际值及对应轮次。没有某项证据时明确标为未产生。工程测试与业务检查分开显示。工程测试可读取实际运行留下的报告，不要求从页面启动整个测试套件。

## 信息与视觉方向

产品气质为精密、安静的技术工作台。首屏的主视觉就是可操作的对话与执行过程，避免让宣传区挤占工作空间。界面使用中文动作名称，技术标识保留原文。

```text
+--------------------------------------------------------------------+
| AutoTariff Agent                    本地连接状态    当前任务调用用量 |
+------------------+---------------------------+---------------------+
| 新建会话         | 当前原文件与说明          | 执行过程 / 结果证据 |
|                  |                           |                     |
| 会话列表         | 用户要求                  | 当前动作            |
| 时间与终态       | Agent 实际回复            | 轮次与工具记录      |
|                  |                           |                     |
| 历史证据入口     |                           | 结果表 / 检查问题   |
|                  |                           | 产物 / 工程测试     |
|                  +---------------------------+                     |
|                  | 输入要求或追问      发送  |                     |
+------------------+---------------------------+---------------------+
```

桌面采用约 220 px 的会话栏，中间对话区占剩余空间的六成，证据区占四成。1200 px 以下可折叠会话栏；窄屏按对话、执行、结果切换，保持输入入口可达。正文左对齐，记录表独立横向滚动，不让整个页面溢出。

配色以雾蓝 `#F4F7FB`、白色 `#FFFFFF`、深海蓝 `#162B43` 为底，动作蓝 `#235FE8` 为主强调。待复核用琥珀 `#A56513`，失败用红 `#B13F48`。颜色必须配合文字状态。字体采用本地可用的 Avenir Next 或系统无衬线，中文采用 PingFang SC；代码与坐标使用系统等宽字体。正文约 14 至 16 px，标题约 24 至 28 px。

最有辨识度的元素是贴着对话推进的真实执行时间线。工具开始、结束和新修复轮次可以有克制的状态过渡。避免通用指标卡墙、装饰渐变、满屏终端文本和自动滚动抢走用户阅读位置。键盘焦点清晰，减少动态效果设置生效。

## 状态约定

| 状态 | 用户看到的内容与下一步 |
| --- | --- |
| 空会话 | 选择原文件和说明，输入一次明确要求。没有虚构聊天、工具记录或成功数字。 |
| 读取中 | 区域级加载提示。未读到的统计不显示为零。 |
| 真实执行中 | 当前动作、开始时间、已完成事件和实际用量。没有证据支持时不显示完成百分比。 |
| 历史记录 | 明示历史运行和时间。打开、切换或刷新不发起模型请求。 |
| 离线验证 | 标明离线报告和生成时间。离线通过不等同于实时模型成功。 |
| 连接中断 | 明示连接中断，保留已读内容。重新连接只读取状态，不重复提交消息。 |
| 失败或阻断 | 显示阶段、具体原因、已保存证据和可用下一步。模型不可用、未知说明、预算不足均不得变成演示回复。 |
| 待人工复核 | 使用 REVIEW 或“待复核”。展示待确认项。零检查问题不能自动变成业务 PASS。 |
| 空结果或缺少报告 | 区分真实零记录、尚未产生、产物读取失败，不互相替代。 |

## 编号验收清单

- [ ] AC-01。本地启动命令和访问地址有记录。实际浏览器能够打开页面；1440 px 桌面和约 390 px 窄屏没有页面级横向溢出，核心动作可用。
- [ ] AC-02。选择现有试点输入后发送自然语言要求，产生真实持久消息与真实运行 ID。证据能追溯到既有 Pi Agent Loop、模型回执和业务账本，不能只调用展示用脚本。
- [ ] AC-03。运行中至少一个工具的开始与结束在完成前可见。页面刷新后仍能读到相同运行及事件。刷新、重复点击和网络重连不会重复提交同一收费请求。
- [ ] AC-04。同一会话发送第二条消息，真实 Agent 使用前文和选定结果回答。若第二条要求触发执行，页面明确关联新运行；既有终态和旧轮次未被覆盖。
- [ ] AC-05。浏览器可选择试点文件，也可上传原件和说明并显示所选身份。受支持输入进入真实流程；未知说明或格式在模型调用前阻断且提示原因。测试上传后必须核对实际运行使用的输入。
- [ ] AC-06。修复运行按轮次展示，能从检查问题追溯到下一轮脚本或直接响应和新检查。至少用一份真实修复证据核对；使用历史证据时明确标识，不能假称当前正在修复。
- [ ] AC-07。结果表记录与后处理产物一致。抽样记录可核对原文坐标。轮次切换会切换对应产物和报告。结果、原始记录、脚本或直接响应、报告可查看或下载，且只暴露已登记产物。
- [ ] AC-08。页面同时能检查工程测试报告和业务检查报告，显示各自来源与时间。REVIEW、FAIL、BLOCKED 与工程 PASS 不混淆。缺报告时显示缺失，不填造统计。
- [ ] AC-09。历史浏览、离线验证、实时执行有文字区分。只有用户发送或明确执行才产生真实模型请求。没有密钥时仍可浏览已有证据，发送失败明确说明模型未配置。
- [ ] AC-10。用真实边界或受控离线测试验证空会话、加载、连接中断、预算拒绝、上传拒绝、待复核和产物缺失状态。所有可见按钮有实际行为，输入支持键盘操作且焦点可见。
- [ ] AC-11。本次任务最多 1000 次实际模型请求，使用独立任务身份登记。旧任务账本、旧用量和旧上限保持原值。每个运行仍有有限调用、轮次、Token 和时间预算。预检拒绝不计为实际请求；不确定请求保留占用且不自动重试。
- [ ] AC-12。产品验收附真实浏览器截图、关键操作结果、离线测试结果和至少一次真实对话闭环的运行 ID。演示数据和测试替身不能代替真实闭环。验证材料记录未通过项。

验收逐项给出 PASS、ISSUES 或 BLOCKED。修正只能服务以上条目。MVP 不增加企业管理、登录权限、计费系统、云端部署、业务批准流程、通用编排平台或任意新单证规则解释。

## 事实依据与协调点

读取依据为 `README.md`、`docs/design-synthesis.md`、`src/index.ts`、`src/closure/models.ts`、`src/closure/live-budget.ts`、`src/closure/runtime.ts` 与 `config/llm/system-prompt.md`。当前 `runPi` 对终态直接返回，`resumeForRepair` 只允许有限恢复，继续对话需要明确处理该边界。当前 `LiveAudit` 使用旧任务固定身份，新任务预算需要独立接入。

Experience First 原则使本轮只保留完成一次真实对话和复核所需的控件。frontend-design 指导使真实执行时间线成为视觉重点。工程实现可选择轮询或事件流，但必须满足可观察的运行状态和重连语义。
