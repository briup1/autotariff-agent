# Ticket 01 UI 优化设计

范围：方案库、归档、改名、停用和恢复；不改 API、数据契约及 Ticket 02。采用紧凑列表而非继续堆叠说明文字，以便跨行核对供应商、状态和最近使用。

示例：确认“怡升昌周报”契约 → 归档表单核对契约与名称 → 保存 → 方案库显示已确认、尚未使用、暂无结论。

## 页面与状态

- 库弹窗宽 960px，表单宽 600px；均限于视口减 32px、高度减 32px并可纵向滚动。库在视口 <900px 时切卡片，表单 <600px 时字段堆叠。长名称/供应商/类型完整换行，契约下拉另有完整文本摘要，不依赖原生选项截断。
- 库显示标题、数量、字段标题和列表；状态用文字加颜色，保留真实最近使用/结论。空库显示原文件→确认→归档步骤与既有入口。
- 读取库立即打开弹窗，显示忙态；失败显示就地错误和重试按钮，不显示假空态。归档也先打开空表单显示读取状态，失败就地重试；无确认契约显示明确引导，不提交。
- 每次库/归档打开使用递增序号，关闭使当前请求失效；响应只允许更新仍打开且序号相同的弹窗。重复打开在当前弹窗打开时忽略；读取重试禁用在途按钮。关闭后迟到响应不打开弹窗，不覆盖后续编辑。
- 表单分“确认契约”和“方案信息”；归档前填已知值，空值保持可编辑。保存只在请求在途禁用关闭/Esc/重复保存；请求结束恢复取消与 Esc。字段错误关联说明，忙态/错误在当前弹窗内公告；成功在库内公告。
- 归档首次提交冻结 requestId + 完整 payload。网络/无效成功响应属于结果不确定：保留 payload，锁定字段，说明“重试原提交”；允许退出，但下次归档先恢复未决提交（不能开启另一份归档）。重试只发送原 payload。HTTP 4xx 明确拒绝（408 除外，如重名；5xx 与解析失败仍为不确定）解除冻结，允许修改，下一次使用新 requestId。只有有效成功确认才清除未决提交。改名为同值幂等，也固定未决 payload。客户端不擅自判断服务端是否保存。
- 库内改名取消回到原按钮；保存或状态更新重绘后，按 planId 找到新改名/状态按钮回焦，缺失回到库关闭按钮。直接从确认契约进入归档，取消回原触发点；成功打开库并聚焦新方案改名按钮。库关闭回入口。公告置于活动 dialog 内，外部 toast 只作为补充。
- 状态操作保留原生确认；请求在途禁用该行操作，显示“正在停用/恢复”；结束后库内显示明确成功/失败并恢复焦点。
- 操作目标至少 44×44px，内容文字至少 12px；可见焦点使用现有蓝色，正文/辅助文字对比度 >=4.5:1。控件边界及焦点指示对比度 >=3:1。沿用全局 prefers-reduced-motion，不添加额外动效。

## 验证

先补失败行为测试：不确定响应后篡改字段仍重试原提交；明确重名拒绝可改；加载关闭/重开及迟到响应；库错误重试；保存忙态、错误清除及状态反馈。保留现有幂等/取消测试。

最终运行 web 相关测试和 typecheck。内置浏览器使用隔离契约 fixture，检查 375/768/1024/1440 的长字段列表和表单、空态/加载/错误/成功、键盘 Tab/Esc、嵌套回焦、44px目标、横向溢出与 reduced-motion。截图作为候选视觉证据人工查看；不冒充独立 QA 或真实读屏测试。

## 评审回应

- UI01-R1 accept：冻结未决提交快照，区分明确拒绝和结果不确定，新增错配反例及重名修正测试。
- UI01-R2 accept：按打开序号隔离响应，关闭失效、重复打开忽略、读取中禁用重试。
- UI01-R3 accept：以上规定各层回焦、仅在途阻止关闭、活动 dialog 内公告；VM 测试不替代真实键盘证据。
- UI01-R4 accept：960/600 宽度、900/600 断点、160字长字段四视口验证。

风险：仅修改 web 三文件与直接测试；不新增依赖。无 RunBinding 投影，保持既有运行信息，不伪造绑定；不验证真实供应商抽取和业务准确性。
