# 对话工作台接入设计

## 使用方式

用户在本机页面选择一份文件和对应说明，发送抽取要求。页面显示真实工具动作、修复轮次和结果。用户可以在同一个会话中继续追问。终态后续请求创建关联新运行，保留旧结果和旧终态。

## 选定架构

采用候选 A 的同进程本地 HTTP 服务与轮询界面。继续使用已有 runPi 和 ClosureRuntime，不另建抽取循环。前端使用无构建静态 HTML、CSS 和 JavaScript，不增加框架依赖。

跨模型评审建议以 A 为基础，吸收候选 B 的持久命令登记及受控证据投影。产品未要求工作进程崩溃时 HTTP 仍在线，因此不引入子进程协议和第二套运行恢复状态。

接口的数据形状先定义在 src/web/types.ts。会话包含消息和关联运行，运行包含真实动作、执行轮次、检查问题和许可产物。业务执行状态仍以 closure.sqlite 为准。网页会话和请求身份存入单独的 SQLite。重复 requestId 返回原消息和运行，不再次调用模型。

## 接入边界

HTTP 服务只绑定 127.0.0.1。服务端检查 Host、Origin、内容类型、体积、上传类型和许可产物身份。浏览器不能指定任意本机路径，也不能读取模型原始请求、模型原始响应、密钥或 SQLite 文件。

runPi 增加可选 requestId 和 assistant 文本观察回调。回调只发布实际已提交的 assistant 文本，不发布隐藏推理。网页查看证据不申请运行写者权限，不消耗模型工具预算。

新运行显式绑定 visual-center-2026-11-03 预算。用户授权最多 1000 次实际模型请求。原 all-batches-2026-11-03 行和动作保持。单运行原有模型、脚本轮次、Token 和时间限制保持。预算预检拒绝不能计为实际调用。回执不确定仍保留预占并阻断自动重试。

## 产品和视觉选择

采用产品经理冻结的对话主区和证据侧栏。比较过对话工作台与运营仪表盘，后者会把发消息和修复过程挤到次要位置，因此未采用。配色使用雾蓝底、白色面板和钴蓝操作色，字体使用本机 Avenir Next 和 PingFang SC。只给实际执行状态添加克制动画。

ui-ux-pro-max 两次查询均返回 FAQ 落地页，未匹配本产品的任务工作台，因此不采用其布局推荐。无障碍、焦点、响应式和减少动态效果按该技能通用规则检查。

### 历史结果的核价布局例外

2026-11-23：历史「结果」标签在无选中工作会话时，以单证据区替代聊天空态双栏；紧凑页头保留只读身份、来源名称、新建会话及原有运行／轮次／导航。该区域结果表使用 13px 单元格与 12px 表头，不以缩放或过小字号塞入业务列。核心字段仅按已知键重排，未知键与缺失值语义不变，长值保留 `title`，表格容器仍可聚焦和局部横移。隐藏聊天区域设为 `inert`，跳转链接改指可见的刷新入口；其他标签和工作会话立即恢复。767px 和 1199px 的既有导航断点不变，Excel 对话框不在该结果样式选择器内。

数据流仍为原 `RunDetail.records` → 一张结果表；不改投影、后处理、导出、工作簿预览或下载。只读合成服务和真实浏览器核验见 `docs/evidence/history-result-review/README.md`，不代表业务准确率或实际模型验收。

## 实施与验证

前端只写 web/，后端只写 src/web/ 与对应测试。协调者维护共享类型、Pi 接入和预算。产品经理按固定 AC-01 至 AC-12 验收，可以提出修正，不能追加业务范围。

类型检查和原有 54 项离线测试已在开始前执行通过。新增 API 验证覆盖输入边界、重复请求、历史读取、后续消息和产物安全。最终在真实浏览器验证发送、进度、刷新、上传、轮次和结果，并记录实际模型回执。
