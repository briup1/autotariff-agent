## 后端安全修复后的实施方案（daf9464，2026-11-15）

本轮只修改 web/app.js、web/index.html、web/styles.css、前端测试与交付文档。后端不再修改。POST /api/contracts/approve 已要求 runId、requirementsDigest、contractSha256，并校验终态 REVIEW、candidate、运行快照、当前登记内容、报告 REVIEW 且 issues 空数组；重复请求幂等。

页面流：以“上海宁波深圳运价表.xlsx”为例，模型生成候选 → 聊天尾部与运行摘要提供“查看并确认契约” → 弹窗只读加载当前运行最新轮次及登记契约快照 → 人核对来源、说明文件名、版本、摘要、字段来源、检查规则、notes/questions、完整原文 → 人点击“批准这份契约” → 明确显示批准成功 → 人可另行归档。取消只关闭和恢复焦点，零 POST、零模型请求。

状态判定：仅 TERMINAL + REVIEW + candidate + 无 run.error/modelFailure + 最新轮次 reportStatus=available、validationStatus=REVIEW、issueCount=0 + run.issueCount=0 才显示“等待人工确认契约”。其他 candidate 显示“候选契约需核对”，真实 BLOCKED/findings 显示阻断或检查问题，不替换原问题。聊天历史原样保留；当前状态卡片澄清正常等待不是操作失败，批准也不改变原运行结论。历史运行仍可只读预览，最终是否可批准由服务端判定。

预览必须重新 GET /api/runs/:id（不继承用户正在看的旧轮次），再 GET /api/artifacts?runId=...&path=登记contract产物。摘要来自本次详情，核对 contract.requirementsDigest/version 与运行绑定，并对完整未截断字符串用浏览器 SHA-256 校验；缺少摘要、产物、报告、解析失败、截断或不匹配一律禁用批准。说明来自该会话的来源登记名称（找不到则明确未登记；observed 显示“从原文观察生成，未上传说明”）。规则摘要使用既有 Contract 字段、来源和检查 quote，不编造业务说明。显示完整摘要 title 与短摘要，并提供完整 JSON。

加载显示进行中；失败保留错误及“重新读取”；空/未知不当作零问题。原生 dialog 约束焦点、Escape 取消、关闭恢复触发点；异步响应以预览对象身份判定，取消后迟到响应不重开、不污染新弹窗。提交中禁用重复批准和关闭。POST 409 等明确拒绝保留人话错误，禁用批准、要求重新读取核对；网络/回包不完整/缺少匹配回执标记“确认结果待核实”，不自动重提。用户可只读核实来源当前状态与归档候选，不能把全局 confirmed 当作同 SHA 成功。POST 返回匹配 run preview 的摘要和版本回执才显示成功；刷新与归档是独立动作，失败不得改写“批准成功”。
